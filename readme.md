# Движ — спорт в компании

Платформа, где люди находят компанию для спорта рядом с домом: пробежка в парке, шахматы в кафе, футбол во дворе. Участник находит встречу в ленте или на карте и записывается сразу или по заявке. Организатор выбирает место на карте из справочника площадок и сразу видит, с кем договориться. Клубы и сообщества публикуют встречи после проверки администратором.

Прототип для финала Чемпионата России по продуктовому программированию, кейс «Столото». Демо-данные — по Красноярску.

## Что умеет

- **Лента и карта встреч.** Поиск по виду спорта, месту и дате; шесть самых популярных видов спорта значками; лента по дням рядом с картой.
- **Создание встречи** участником или допущенной организацией. Вид спорта выбирается из списка или вписывается свой — он сразу появляется в каталоге и поиске без правок кода.
- **Два режима записи.** Свободная запись и запись по заявке: заявка ждёт решения, организатор принимает или отклоняет. Есть лимит мест, организатор может закрыть запись.
- **Панель организатора** в карточке встречи, блок «Вы организатор» справа: участники, заявки, решения по ним.
- **Обсуждение под встречей.** Вопросы и ответы веткой, автор встречи отмечен плашкой «Организатор».
- **Организации.** Заявка на допуск → решение администратора → публичная страница клуба и его встречи. До допуска публиковать нельзя.
- **Админка.** Поиск организаций и встреч, допуск и отказ с причиной, снятие с публикации и удаление встречи, скрытие сообщений, журнал действий.
- **Киллер-фича «Место встречи».** При создании встречи место выбирается на карте из справочника площадок. Подходящие для вида спорта площадки подсвечены: шахматам — кафе и клубы, футболу — поля и залы. В карточке площадки — часы работы и контакт, с кем договориться. Можно поставить свою точку на карте или найти адрес поиском.
- **Отзывы и надёжность.** После встречи участник оценивает организатора, а организатор отмечает, кто пришёл. Отзывы слепые: нельзя ответить плохой оценкой на плохую. Средняя оценка видна от трёх отзывов, в заявке организатор видит надёжность участника: «приходит на 6 из 6».
- **Понятно всем возрастам.** Текст от 16 px, кнопки от 48 px, статусы с иконкой и подписью; работает на компьютере и телефоне.

## 2. Инструкция по запуску

### Что нужно

- Node.js 24 LTS;
- pnpm 10: `npm install -g pnpm@10.34.6` или `corepack enable`;
- PostgreSQL 17 — в Docker или установленный.

### Запуск локально

```bash
# 1. Зависимости и настройки
pnpm install
cp .env.example .env

# 2. База данных — один из вариантов:
docker compose up -d          # а) PostgreSQL в Docker
# б) установленный PostgreSQL: один раз создать пользователя и базу sport с паролем sport
#    psql -U postgres -h 127.0.0.1 -c "CREATE ROLE sport LOGIN PASSWORD 'sport'" -c "CREATE DATABASE sport OWNER sport"

# 3. Таблицы и демо-данные
pnpm db:push                  # создать таблицы по схеме
pnpm db:seed                  # загрузить демо-данные (база очищается)

# 4. Запуск: интерфейс http://127.0.0.1:5173, API http://127.0.0.1:3000/api/health
pnpm dev
```

Если `db:push` просит подтверждение при изменении схемы, запустите `pnpm db:push --force`.

Как на сервере: `pnpm build && NODE_ENV=production pnpm start`. Тогда один процесс на порту `PORT` отдаёт и API, и собранный интерфейс: http://127.0.0.1:3000.

### Переменные окружения

Пример — [`.env.example`](.env.example), сервер проверяет их при старте.

| Переменная | По умолчанию | Зачем |
| --- | --- | --- |
| `DATABASE_URL` | `postgres://sport:sport@127.0.0.1:5432/sport` | Подключение к PostgreSQL |
| `PORT` | `3000` | Порт сервера |
| `SESSION_TTL_DAYS` | `7` | Сколько дней живёт сессия |
| `SEED_ON_START` | `false` | `true` на деплое: при старте загрузить демо-данные, если их версия в коде новее записанной в базе |
| `GEOCODER_URL` | `https://nominatim.openstreetmap.org` | Поиск адреса в форме встречи; пусто — место выбирается только на карте |

### Деплой на Render

1. Render Dashboard → New → Blueprint → этот репозиторий. Render прочитает [`render.yaml`](render.yaml), создаст базу `vmeste-db` и сервис `vmeste` во Франкфурте и сам пропишет `DATABASE_URL`.
2. Сборка: `pnpm install --frozen-lockfile && pnpm build && pnpm db:push --force`. Запуск: `pnpm start`. Проверка здоровья: `/api/health`.
3. При первом старте `SEED_ON_START=true` загружает демо-данные. Перезапуск и пробуждение сервиса их не стирают: данные перезаливаются, только если в коде поднята `SEED_VERSION` (`apps/api/src/db/seed/index.ts`).

## 4. REST API

Все пути начинаются с `/api`, тела запросов и ответов — JSON. Вход — сессия в cookie `sid` (HttpOnly). Права проверяются на сервере по роли из сессии, а не только скрываются в интерфейсе. Ошибка всегда одного вида, `message` — готовый текст для человека:

```json
{ "error": { "code": "ORG_NOT_APPROVED", "message": "Организация ещё не допущена администратором" } }
```

## 5. Демонстрационные сценарии

Все шесть сценариев ТЗ проходят на демо-данных. Даты встреч считаются от момента загрузки данных, поэтому ближайшие встречи всегда в ближайшие 1–9 дней. Время показывается в часовом поясе вашего устройства.

### Сценарий 1. Участник создаёт встречу со своим видом спорта

1. «Войти как участник» → «Создать встречу».
2. В блоке «Чем займёмся?» выбрать плитку «Своё» и вписать новый вид спорта, например «Падел».
3. Заполнить название, дату и время, место (на карте или поиском адреса), режим записи → «Опубликовать встречу».
4. Новый вид спорта сразу появляется в каталоге и поиске, код не менялся. Вид, уже добавленный пользователем в демо-данных, — «Скандинавская ходьба».

### Сценарий 2. Допуск организации и публикация

1. Войти как `org.pending@demo.local` → «Кабинет организации»: заявка «На проверке», публиковать встречи нельзя.
2. «Войти как администратор» → «Админка» → «Организации» → «Утренний пульс» → «Одобрить» (или «Отклонить» с причиной).
3. Снова войти как `org.pending@demo.local` → «Создать встречу» → встреча публикуется сразу и видна в ленте и на странице организации.

Отклонённая заявка с причиной — у `org.rejected@demo.local`: её можно исправить и подать заново.

### Сценарий 3. Свободная запись

1. «Войти как участник» → «Шахматный вечер в кафе» → «Записаться». Статус «Вы в списке участников» и число мест обновляются сразу.
2. «Войти как организация» → та же встреча → блок «Вы организатор» → «Участники»: Иван Петров в списке.

Встреча «Плавание для начинающих» заполнена (2 из 2), записаться на неё нельзя.

### Сценарий 4. Запись по заявке

1. «Войти как участник» → «Блиц-турнир клуба «Е2–Е4»» → «Отправить заявку» (можно с сообщением). Статус: организатор рассмотрит заявку.
2. «Войти как организация» → та же встреча → блок «Вы организатор» → «Ждут решения»: заявку Ивана «Принять», другую — «Отклонить».
3. Участник видит новый статус в карточке встречи и в «Моих мероприятиях».

Заявки рассматривает автор встречи, а не администратор. Так же работает «Волейбол в «Динамике»» у Ивана Петрова: две заявки ждут его решения.

### Сценарий 5. Вопрос и ответ в обсуждении

1. «Войти как участник» → «Блиц-турнир клуба «Е2–Е4»» → «Обсуждение» → «Ваш вопрос» → «Отправить».
2. «Войти как организация» → та же встреча → «Ответить». Ответ встаёт веткой под вопросом, у автора плашка «Организатор».

Готовые вопрос и ответ — под «Шахматным вечером в кафе» и «Дворовым футболом 5×5».

### Сценарий 6. Снятие встречи администратором

1. «Войти как администратор» → «Админка» → «Мероприятия» → любая встреча → «Снять с публикации», указать причину.
2. Встречи больше нет в ленте, поиске и на карте. По прямой ссылке записаться нельзя: организатор и записавшиеся видят «Публикация недоступна» и причину.

Уже снятая встреча — «Продаю абонемент в спортзал»: Иван Петров записан на неё и в «Моих мероприятиях» видит «Публикация недоступна».

### Что ещё посмотреть

- **«Место встречи».** «Создать встречу» → «Шахматы»: на карте подсвечены кафе и клубы, в карточке площадки — контакт администратора. Для футбола подсвечены поля и залы, можно поставить свою точку. На главной лента и карта встреч стоят рядом, на телефоне — переключатель «Список / Карта».
- **Отзывы.** `user1` → «Мои мероприятия» → «Прошедшие» → «Вечерняя пробежка по набережной» → «Оценить встречу». После отзыва в профиле Ивана открывается отзыв о нём.
- **Отметка участников.** `user1` → «Мои мероприятия» → «Я организую» → «Прошедшие» → «Волейбол: вечерняя игра» → «Отметить участников».
- **Надёжность.** «Войти как организация» → «Блиц-турнир клуба «Е2–Е4»» → блок «Вы организатор», заявки: у Марии «приходит на 6 из 6», у Алексея — «2 из 3» и неявка.
- **Закрыть запись.** Автор встречи в блоке «Вы организатор» нажимает «Закрыть запись»: новые записи не принимаются, записанные остаются.
- **Модерация обсуждения.** Под «Утренней пробежкой в Центральном парке» одно сообщение скрыто администратором.

Все демо-данные и где что лежит — [docs/DEMO_DATA.md](docs/DEMO_DATA.md).

| --- | --- |
| Гость | Смотреть ленту, карту, карточки встреч, обсуждения, страницы организаций и профили |
| Участник | Создавать встречи, в том числе со своим видом спорта; записываться и подавать заявки; задавать вопросы; рассматривать заявки на свои встречи; оставлять отзывы |
| Организация | До допуска — заполнить заявку и ждать решения, публиковать нельзя. После допуска — публичная страница, встречи от имени организации, панель организатора |
| Администратор | Допускать и отклонять организации (отказ — с причиной), снимать встречи с публикации и удалять, скрывать сообщения. Заявки участников не рассматривает |

- Права и статусы проверяются на сервере, интерфейс только не показывает недоступные кнопки.
- Заявки на встречу рассматривает только её автор.
- Снятая или удалённая встреча пропадает из ленты, поиска и карты, записаться на неё нельзя даже по прямой ссылке. Организатор и записавшиеся видят «Публикация недоступна» и причину, остальные — что встреча не найдена.
- Удаление мягкое: запись остаётся в базе. Все решения администратора попадают в журнал.
- Нельзя записаться на свою, прошедшую или заполненную встречу и на встречу с закрытой записью. Два человека не займут одно последнее место: запись идёт в транзакции с блокировкой строки встречи.
- Отзыв оставляет только подтверждённый участник прошедшей встречи, в течение 14 дней. Отзывы слепые: отзыв об организаторе виден, когда тот отметил участников, а отметка об участнике — когда участник сам оценил встречу; после 14 дней видно всё.
- Пароли хранятся только как хэш Argon2id. Роль администратора регистрацией не получить. Частота попыток входа и регистрации ограничена.

## 7. Имитации и ограничения

**Имитации**

- Люди, организации, площадки и контакты в демо-данных вымышленные, телефоны вида `+7 900 000-01-NN`. Реальные только названия двух парков, без контактов.
- Демо-аккаунты с общим паролем и кнопки быстрого входа — только для проверки. Регистрация и вход при этом настоящие.
- Уведомлений нет: статус заявки участник видит в карточке встречи и в «Моих мероприятиях».
- Площадки не бронируются: в карточке площадки только контакт, с кем договориться.

**Ограничения**

- Бесплатный Render: сервис засыпает после 15 минут простоя, первый запрос — до минуты. Бесплатная база Render Postgres живёт 30 дней с момента создания, затем 14 дней отсрочки и удаление.
- Демо-данные и поиск адреса — по Красноярску. Поиск адреса идёт через бесплатный Nominatim с лимитом около одного запроса в секунду. Если поиск или карта недоступны, встречу всё равно можно создать и открыть: адрес хранится текстом.
- Даты демо-встреч считаются от загрузки данных. Окно отзывов — 14 дней, поэтому со временем прошедшие демо-встречи из него выйдут; свежие даты даёт повторная загрузка (`pnpm db:seed` локально или новая `SEED_VERSION` на деплое).
- Нет оплаты, личных сообщений, бронирования площадок, построения маршрутов и восстановления пароля.

```bash
pnpm typecheck     # типы во всех пакетах

```
