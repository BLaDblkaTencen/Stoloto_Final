# Краткая выжимка ТЗ (полный PDF — в чате команды)

Обязательный минимум:
- 3 роли: пользователь, организация/сообщество, администратор. ТЗ разрешает имитировать вход, но мы делаем настоящую регистрацию и вход и оставляем демо-аккаунты для проверки. Бизнес-логика должна быть настоящей.
- Мероприятия: создание пользователем или допущенной организацией, поиск/лента, карточка (название, описание, направление, организатор со ссылкой на профиль, дата/время/место, режим записи, условия).
- Направление спорта: список + свой вариант БЕЗ правки кода (каталог в БД).
- 2 режима записи: свободное присоединение / по заявке (ожидает → принята/отклонена). Оба работают.
- Организатор видит участников и заявки; пользователь видит статус своей записи.
- Обсуждение под событием (комментарии, авторство различимо). Вопрос может задать любой пользователь.
- Организация: профиль -> заявка на допуск -> решение админа -> страница и события (публикуются сразу). До допуска публиковать нельзя.
- Админ: поиск организаций и событий, допуск/отклонение (с причиной), удаление/снятие события с публикации. На снятое событие нельзя записаться, даже по прямой ссылке; организатору и записавшимся видно, что публикация недоступна.
- Админ НЕ рассматривает заявки участников — это делает автор события.
- UI понятен старшему поколению, адаптив (desktop + mobile).
- Демо-данные: разные виды спорта, оба режима, организация до/после допуска, заявки на рассмотрение.
- Сдача: репозиторий GitVerse, README (стек, запуск, структура), демо-доступы, описание сценариев/правил/имитаций/ограничений, презентация, деплой по сети.

Сценарии проверки: 1) создание события юзером (в т.ч. новый вид спорта) 2) допуск организации и публикация 3) свободное присоединение 4) запись по заявке (принять и отклонить) 5) вопрос-ответ в обсуждении 6) снятие события админом.
