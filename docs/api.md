# Контракт API

Здесь описываем всё, через что общаются фронт и бэк. Меняешь контракт — меняешь этот файл в том же PR.
У каждого участника свой раздел: свой раздел правишь сам, в чужом — запись в [REQUESTS.md](REQUESTS.md). Так правки троих не конфликтуют.

## Общие правила

- Все пути начинаются с `/api`. Тела запросов и ответов — JSON.
- **Вход:** сессия в cookie (`HttpOnly`), браузер отправляет её сам. Права проверяются на сервере по роли из сессии.
- **Ошибки** в едином формате, `message` — готовый текст для пользователя:
  ```json
  { "error": { "code": "VALIDATION_ERROR", "message": "Проверьте заполнение полей", "details": [{ "path": "title", "message": "..." }] } }
  ```
  | `code` | HTTP | Когда |
  | --- | --- | --- |
  | `VALIDATION_ERROR` | 400 | неверные данные; `details` — по полям |
  | `UNAUTHORIZED` | 401 | не выполнен вход |
  | `FORBIDDEN` | 403 | нет прав на действие |
  | `NOT_FOUND` | 404 | нет такого объекта или он недоступен этому пользователю |
  | `CONFLICT` | 409 | действие противоречит состоянию (уже записан, мест нет) |
  | `RATE_LIMITED` | 429 | слишком много попыток |
  | `INTERNAL` | 500 | ошибка сервера |
- Типы ошибок — `packages/shared/src/errors.ts`, на сервере — `AppError` и `errors.*` из `apps/api/src/lib/errors.ts`.
- Схемы запросов и ответов — Zod в `packages/shared/src/schemas/<модуль>.ts`.
