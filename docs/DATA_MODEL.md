# Модель данных (единая для всех)

Это источник правды по сущностям. Менять можно только отдельным маленьким PR с пометкой в чате: на этом файле строятся API, база и интерфейс всех трёх участников.
Типы здесь условные. Конкретные типы PostgreSQL и ограничения базы — в [DB_SCHEMA.md](DB_SCHEMA.md) и коде `apps/api/src/db/schema`; при расхождении правится то, что отстало, отдельным PR. Имена полей — `snake_case` на английском. Идентификаторы — UUID, в API отдаются строкой. Время хранится в UTC (ISO 8601), отображается в локальном часовом поясе.

## Связи

```
User 1──* Registration *──1 Event *──1 Sport
User 1──0..1 Organization ──* OrganizationSport *──1 Sport
User 1──* Event (создатель)        Event *──0..1 Organization (от имени)
Event 1──* Comment *──1 User       Comment *──0..1 Comment (ответ)
Event 1──* Review *──1 User (автор)  Review *──0..1 User | Organization (о ком)
User/Admin 1──* AuditLog
User 1──* Session
User 1──* UserSport *──1 Sport
Event *──0..1 Venue            Sport 1──* SportVenueType (подходящие типы площадок)
AppMeta — служебная таблица без связей
```

## Кто меняет данные

Таблицы распределены по владельцам в [OWNERSHIP.md](OWNERSHIP.md) и [DB_SCHEMA.md](DB_SCHEMA.md). Два исключения, чтобы никому не приходилось править чужой модуль:

- **Поля решений администратора** меняет только модуль `admin` (участник 3), владельцы таблиц их только читают:
  `Organization.status` (кроме повторной подачи заявки), `rejection_reason`, `reviewed_by`, `reviewed_at`;
  `Event.status`, `moderation_reason`, `moderated_by`, `moderated_at`;
  `Comment.is_hidden`, `hidden_by`, `hidden_reason`.
- **Решение по заявке участника** панель организатора (участник 2) принимает через сервис модуля `registrations` (участник 1), а не своим SQL: правила переходов статусов живут в одном месте.

## Роли аккаунтов

`User.role`: `user` | `organization` | `admin`.
Аккаунт с ролью `organization` — это представитель. У него ровно одна `Organization`. Один аккаунт — одна роль. Демо-аккаунты всех трёх ролей лежат в сиде ([DEMO_DATA.md](DEMO_DATA.md)).

**Регистрация и вход — настоящие (email + пароль).** При регистрации выбирается тип аккаунта: «Участник» (`user`) или «Представляю организацию» (`organization`). **Роль `admin` регистрацией получить нельзя**, админ создаётся только сидом. Не делаем: подтверждение почты, SMS, восстановление пароля, вход через внешние сервисы (ТЗ их не требует).
**Организатор мероприятия — не роль.** Это `Event.created_by` плюс, если указана, `Event.organization_id`. Событие от имени организации создаёт аккаунт `organization` с одобренной `Organization`. Такой аккаунт создаёт события только от имени своей организации: `organization_id` ставит сервер, выбора организатора в форме нет.

## Sport — вид спорта (каталог в БД)

| Поле       | Тип        | Правила                                                  |
| ---------- | ---------- | -------------------------------------------------------- |
| id         | id         |                                                          |
| name       | string     | как показываем: «Футбол»                                 |
| slug       | string     | **уникальный**, нормализованный (см. ниже)               |
| is_custom  | bool       | `true`, если добавлен пользователем при создании события |
| created_by | id → User? | у стартового списка пусто                                |
| created_at | datetime   |                                                          |

**Нормализация «своего» вида спорта** (создание нового спорта не меняет код):

1. Обрезать пробелы по краям, схлопнуть повторные пробелы, длина 2–40 символов.
2. `slug` = нижний регистр, `ё`→`е`, лишние знаки убраны.
3. Если `slug` уже есть — использовать существующий спорт, дубль не создавать.
4. Иначе создать `Sport` с `is_custom = true`. Он сразу доступен в фильтрах и списках.

**Подходящие площадки:** `SportVenueType(sport_id, venue_type)` — какие типы площадок подходят виду спорта (нужны для подсказки на карте). Например: шахматы → `cafe`, `club`; футбол → `field`, `hall`; бег → `park`. У своего вида спорта типов нет, карта показывает все площадки. Владелец связки — участник 2 (карта).

Стартовый список (сид): футбол, баскетбол, волейбол, бег, шахматы, йога, зарядка во дворе, настольный теннис, плавание, велоспорт.

| Поле                   | Тип        | Правила                                                        |
| ---------------------- | ---------- | -------------------------------------------------------------- |
| id                     | id         |                                                                |
| owner_id               | id → User  | аккаунт-представитель, уникален                                |
| name                   | string     | уникально среди `approved`                                     |
| description            | text       | чем занимается                                                 |
| activity               | string     | вид деятельности (клуб, кружок, федерация, компания)           |
| city                   | string?    |                                                                |
| contacts               | string?    | почта, телефон, ссылка на соцсеть                              |
| status                 | enum       | `pending` / `approved` / `rejected`                            |
| rejection_reason       | text?      | обязательно при `rejected`                                     |
| reviewed_by            | id → User? | админ                                                          |
| reviewed_at            | datetime?  | обязательны вместе с `reviewed_by` при `approved` / `rejected` |
| created_at, updated_at | datetime   |                                                                |

**Правила:**

- `pending`: организация видит свою заявку и статус. Публичной страницы нет (для всех, кроме владельца и админа — 404). Создавать события нельзя.
- `approved`: публичная страница открыта, события публикуются сразу.
- `rejected`: видна причина. Представитель может поправить данные и отправить заново (статус снова `pending`, причина очищается).

## Venue — площадка (киллер-фича «Место встречи»)

| Поле          | Тип      | Правила                                                                 |
| ------------- | -------- | ----------------------------------------------------------------------- |
| id            | id       |                                                                         |
| name          | string   | «Кафе «Ход конём»»                                                      |
| type          | enum     | `cafe` / `club` / `field` / `hall` / `pool` / `park` / `yard` / `other` |
| address       | string   |                                                                         |
| lat, lng      | decimal  | координаты на карте                                                     |
| description   | text?    | чем удобна: столы, раздевалки, покрытие                                 |
| working_hours | string?  | «ежедневно 10:00–22:00»                                                 |
| contact_name  | string?  | контактное лицо, например «Ирина, администратор»                        |
| contact_phone | string?  |                                                                         |
| contact_note  | string?  | как договориться (звонить до 20:00 и т.п.)                              |
| created_at    | datetime |                                                                         |

- Справочник площадок наполняет сид. Создания и модерации площадок в интерфейсе в базовой версии нет.
- Контакты **вымышленные**, публичные (видны всем). Реальных людей и организаций в данных нет.
- Событие без площадки допустимо: тогда указывается только текстовый адрес и, при желании, своя точка `lat`/`lng`.
- Выбор площадки подставляет в событие `venue_id`, `address`, `lat`, `lng`. Адрес можно править вручную.
- Карточка площадки в событии показывается всем, кто видит событие; контакт не скрывается.
- Метки на карте и фильтр: по `type` площадки и по виду спорта события. Подсказка «подходит виду спорта» — по `SportVenueType`.

## Registration — запись на мероприятие

| Поле                   | Тип        | Правила                                            |
| ---------------------- | ---------- | -------------------------------------------------- |
| id                     | id         |                                                    |
| event_id               | id → Event |                                                    |
| user_id                | id → User  |                                                    |
| status                 | enum       | `confirmed` / `pending` / `rejected` / `cancelled` |
| message                | text?      | сообщение организатору при заявке, до 500 символов |
| created_at, updated_at | datetime   |                                                    |
| decided_at             | datetime?  |                                                    |
| decided_by             | id → User? | всегда автор события; обязателен при `rejected`    |

Уникальна пара `(event_id, user_id)`: одна запись, которая меняет статус.

**Переходы статусов:**

| Было → Стало                          | Кто          | Когда                               |
| ------------------------------------- | ------------ | ----------------------------------- |
| — → `confirmed`                       | пользователь | режим `free`                        |
| — → `pending`                         | пользователь | режим `request`                     |
| `pending` → `confirmed` / `rejected`  | организатор  | рассматривает заявку                |
| `confirmed` / `pending` → `cancelled` | пользователь | отменил запись                      |
| `cancelled` → `confirmed` / `pending` | пользователь | записался снова (по режиму события) |
| `rejected` → любой                    | никто        | отказ окончательный                 |

**Правила записи** (проверяются на сервере; при нарушении — понятная ошибка):

- Нельзя записаться на своё событие, на `unpublished` / `deleted`, на прошедшее.
- Нельзя записаться, если организатор закрыл запись (`registration_closed`). Уже записанные остаются и могут отменить запись; ждущие заявки организатор рассматривает как обычно.
- Если задан `capacity` и мест нет — запись невозможна (лист ожидания не делаем).
- Администратор заявки участников не рассматривает.

| Поле          | Тип           | Правила                                                   |
| ------------- | ------------- | --------------------------------------------------------- |
| id            | id            |                                                           |
| event_id      | id → Event    |                                                           |
| author_id     | id → User     |                                                           |
| parent_id     | id → Comment? | ответ в ветке; глубина 1; родитель — в том же мероприятии |
| text          | text          | 1–1000 символов                                           |
| is_hidden     | bool          | скрыто модератором                                        |
| hidden_by     | id → User?    |                                                           |
| hidden_reason | string?       |                                                           |
| created_at    | datetime      |                                                           |

- Ответ организатора — обычный комментарий с `parent_id`; отдельной сущности для ответов нет.
- Писать может любой авторизованный пользователь (в том числе не записанный). Читать обсуждение открытых событий можно без записи.

- Скрытый комментарий показывается как «Сообщение скрыто модератором», текст не отдаётся в API.
- «Удалить сообщение» в админке (задача 3.6) — это скрытие: комментарии, как и события, физически не удаляются.
- На `unpublished` / `deleted` писать нельзя, читать может организатор, записавшиеся и админ.

## Review — отзыв после встречи

Одна таблица на два направления. Участник оценивает организатора встречи — человека или клуб, если встреча от его имени. Организатор отмечает каждого подтверждённого участника: пришёл или нет. Итоги (оценка, надёжность) не хранятся, а считаются запросом.

| Поле                   | Тип                | Правила                                                                                      |
| ---------------------- | ------------------ | -------------------------------------------------------------------------------------------- |
| id                     | id                 |                                                                                              |
| event_id               | id → Event         |                                                                                              |
| author_id              | id → User          | кто оставил; за клуб — его аккаунт, автор события                                            |
| direction              | enum               | `participant_to_organizer` / `organizer_to_participant`                                      |
| target_user_id         | id → User?         | о ком: о человеке…                                                                           |
| target_org_id          | id → Organization? | …или о клубе; ровно одно из двух                                                             |
| attended               | bool?              | только у отметки организатора, обязательно                                                   |
| rating                 | int?               | 1–5; у отзыва участника обязательно, у отметки — по желанию и только тем, кто пришёл         |
| tags                   | string[]           | готовые теги из `REVIEW_TAG_LABELS` (packages/shared): свои для организатора и для участника |
| comment                | text?              | до 500 символов                                                                              |
| created_at, updated_at | datetime           |                                                                                              |

Уникальны тройки `(event_id, author_id, target_user_id)` и `(event_id, author_id, target_org_id)`: один отзыв от человека о встрече и одна отметка о каждом участнике. Повторная отправка правит ту же строку.

**Правила** (проверяются на сервере, модуль `reviews`):

- Оценивает встречу только её подтверждённый участник, не организатор. Отменившие запись и те, чью заявку не приняли, не оценивают. Отмечает участников только автор события, администратор — нет.
- Окно: с окончания встречи (`ends_at`, а без него — через 2 часа после `starts_at`) и ещё 14 дней. В окне отзыв и отметки можно поправить. У снятых и удалённых встреч отзывов нет, в итоги они не входят.
- **Слепые отзывы.** Отзыв об организаторе виден, когда он отметил участников; отметка об участнике — когда участник сам оценил встречу. После окна видно всё. Так нельзя ответить плохой оценкой на плохую.
- **Надёжность участника** — «приходит на N из M»: M — подтверждённые записи на прошедшие опубликованные встречи, неявки — только видимые отметки «не пришёл». Пока организатор никого не отметил, все считаются пришедшими. Отмена записи неявкой не считается.
- **Средняя оценка** видна от трёх отзывов, до этого — «Новый организатор». Округляется до десятых.
- Скрытие отзывов администратором и ответ организатора на отзыв пока не делаем.

## AppMeta — служебные данные

| Поле       | Тип      | Правила                                                  |
| ---------- | -------- | -------------------------------------------------------- |
| key        | string   | первичный ключ; сейчас используется один: `seed_version` |
| value      | string   |                                                          |
| updated_at | datetime |                                                          |

Сид при старте сервера наполняет базу, только если `seed_version` в коде новее записанной. Бесплатный Render засыпает и при пробуждении перезапускает сервер: без этой проверки сид стирал бы данные, созданные экспертами. Чтобы пересоздать демо-данные, нужно поднять версию в коде сида или выполнить `pnpm db:seed` вручную.

| ------------- | ------------- | ------------------------------------------------------------------------------------------------------------------ | --------- |
| `published`   | да            | да                                                                                                                 | да        |
| `unpublished` | нет           | организатору, записавшимся и админу: заглушка «Публикация недоступна» с причиной; остальным — «Событие недоступно» | запрещена |
| `deleted`     | нет           | то же, что для `unpublished`; админ видит данные                                                                   | запрещена |

Существующие записи при снятии события **не удаляются** и не меняют статус: записавшиеся видят событие как «Публикация недоступна». Так проще и понятнее.

## Подписи статусов в интерфейсе (единые для всех)

| Значение                 | Подпись             | Цвет       |
| ------------------------ | ------------------- | ---------- |
| Registration `confirmed` | Вы записаны         | зелёный    |
| Registration `pending`   | Заявка ждёт решения | жёлтый     |
| Registration `rejected`  | Заявка отклонена    | красный    |
| Registration `cancelled` | Запись отменена     | серый      |
| Organization `pending`   | На рассмотрении     | жёлтый     |
| Organization `approved`  | Допущена            | зелёный    |
| Organization `rejected`  | Отклонена           | красный    |
| Event `published`        | Опубликовано        | зелёный    |
| Event `unpublished`      | Снято с публикации  | серый      |
| Event `deleted`          | Удалено             | красный    |
| `join_mode = free`       | Свободная запись    | синий      |
| `join_mode = request`    | По заявке           | фиолетовый |

Состояние никогда не выражаем только цветом: рядом всегда текст и иконка.

## Не входит в модель (пока)

Бронирование и расписание площадок, аккаунты владельцев площадок. Подписки, жалобы, блокировки, повторяющиеся события и уведомления в базовую модель не входят.
