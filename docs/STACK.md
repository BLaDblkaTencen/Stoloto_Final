# Технологический стек

Решение для прототипа. Требования: всё бесплатное и без регистраций для экспертов, быстрый отклик, карта, лёгкая нагрузка, один язык на всех трёх участников.
Это основа для раздела «Стек» в README.md (задача 3.9).

## Структура монорепозитория

```
apps/web        фронтенд (React)
apps/api        сервер (Fastify) и схема БД
packages/shared Zod-схемы и типы сущностей из DATA_MODEL.md
docker-compose.yml   локальный Postgres
.env.example         пример переменных окружения
```

В проде сервер сам раздаёт собранный фронтенд: один процесс, один адрес, без CORS. Фронт и бэк импортируют типы из `packages/shared`, поэтому расхождение контракта ловит компилятор.

## База данных: PostgreSQL

Сущности — по [DATA_MODEL.md](DATA_MODEL.md). Правила для схемы:

- **Идентификаторы:** `uuid` (встроенный `gen_random_uuid()`). Время: `timestamptz` (хранится в UTC).
- **Статусы:** нативные `enum` (`registration_status`, `event_status`, `org_status`, `join_mode`, `venue_type` и т.д.), значения как в DATA_MODEL и в `packages/shared`.
- **Инварианты на уровне БД** (последняя линия защиты, помимо проверок на сервере):
  - `CHECK`: при `org_status = 'rejected'` обязательна `rejection_reason`; при `event_status <> 'published'` обязательна `moderation_reason`.
  - `UNIQUE (event_id, user_id)` в `registrations`; `UNIQUE (slug)` в `sports`; `UNIQUE (owner_id)` в `organizations`.
  - Частичный уникальный индекс на имя среди `approved` организаций.
  - Внешние ключи везде; удаления мягкие (статус), физически события не удаляем.
- **Запись и лимит мест:** транзакция с блокировкой строки события (`SELECT … FOR UPDATE`), чтобы два пользователя не заняли последнее место.
- **Индексы:** `events (status, starts_at)`, `events (sport_id)`, `events (lat, lng) WHERE status = 'published'`, `venues (type)`, `venues (lat, lng)`, `comments (event_id, created_at)`, `registrations (user_id)`.
- **Поиск по тексту:** встроенный полнотекстовый поиск с русской конфигурацией (`to_tsvector('russian', …)`, GIN-индекс) или `pg_trgm` для поиска по части слова. Отдельный поисковый сервис не нужен.
- **Геопоиск:** для карты достаточно `lat`/`lng` и запроса по области (`bbox`). PostGIS не нужен; подключаем позже, только если понадобится «ближайшие ко мне» (он есть у Neon).
- **Подключение:** драйвер `postgres` или `pg`, пул соединений. У Neon использовать **pooled**-строку подключения.

### Схема и данные в прототипе
Схема описывается в `apps/api/src/db/schema/*.ts` (по файлу на модуль, владелец — по OWNERSHIP). Для прототипа **без истории миграций**: `pnpm db:push` синхронизирует схему, `pnpm db:seed` сбрасывает и заново наполняет демо-данными (идемпотентно). Так три человека не сталкиваются на файлах миграций. Если нужна история, миграции генерирует только участник 3 в моменты интеграции.
На деплое (`SEED_ON_START=true`) сид при старте сервера наполняет базу, только если версия демо-данных в коде (`SEED_VERSION`) новее записанной в `app_meta`. Поэтому пробуждение сервиса на Render не стирает созданное экспертами, а новые демо-данные приезжают с деплоем, где подняли версию.

### Переменные окружения (`.env`, в репозиторий не попадает)
Полный список с пояснениями — [`.env.example`](../.env.example), сервер проверяет его при старте (`apps/api/src/env.ts`).
```
DATABASE_URL=postgres://sport:sport@127.0.0.1:5432/sport
PORT=3000
SESSION_TTL_DAYS=7
SEED_ON_START=false
```
Секрет для сессий не нужен: токен сессии случайный, в базе хранится только его хэш.

## Локальная разработка

Вариант 1 (рекомендуется): Docker Compose. Docker Desktop бесплатен для личного и небольшого коммерческого использования, образ `postgres` — открытый.
```
docker compose up -d
pnpm install
pnpm db:push && pnpm db:seed
pnpm dev
```
Вариант 2 (без Docker): установить PostgreSQL с postgresql.org и создать пользователя и базу `sport` (команда — в README).
Вариант 3 (ничего не ставить): у каждого свой бесплатный проект или ветка в Neon, своя `DATABASE_URL` в `.env`.

Каждый участник работает со **своей** базой, общей разработческой БД нет.

## Деплой

- **Приложение:** Render, бесплатный Web Service (Docker или Node-сборка), одна команда запуска. Простаивающий сервис засыпает, первый запрос после этого занимает около минуты.
- **БД:** **Neon**, бесплатный тариф: Postgres без карты, 100 CU-часов в месяц, около 0,5–1 ГБ на проект. Вычисления засыпают после 5 минут простоя, первый запрос после сна чуть медленнее.
- **Не использовать:** бесплатный Postgres от Render (удаляется через 30 дней после создания, после 14 дней отсрочки) и бесплатный Supabase (проект ставится на паузу после 7 дней без активности, а эксперты могут открыть сайт позже).
- **Перед показом экспертам:** открыть сайт заранее и убедиться, что он проснулся. Постоянно «будить» БД пингами не стоит: CU-часов на это не хватит. Условия тарифов меняются, перед деплоем проверить актуальные лимиты по ссылкам ниже.
- **Запасной вариант:** Cloudflare Tunnel с ноутбука (нужна включённая машина) — только если хостинг подведёт.

## Производительность и нагрузка

- Карта грузится отдельным фрагментом (`React.lazy`), лента открывается быстрее.
- Запрос площадок и событий на карте идёт по `bbox`; кластеризация меток на клиенте.
- Серверная пагинация везде; ответы сжимаются; статические файлы с хэшем кешируются надолго.
- TanStack Query: кеш и `staleTime`, оптимистичные обновления при записи на событие.
- Скелетоны вместо спиннеров, аватары-инициалы вместо картинок.
- Для нашей нагрузки (десятки пользователей, сотни событий и площадок) запас на порядки.

## Карта

Leaflet + плитки OpenStreetMap: без ключей, обязательна атрибуция «© OpenStreetMap». Политика OSM рассчитана на умеренное использование: для прототипа достаточно. Если плитки будут недоступны, интерфейс переходит в запасной режим с текстовым адресом (см. [KILLER_FEATURE.md](KILLER_FEATURE.md)). Яндекс.Карты и Google Maps не используем: нужны ключи и регистрация.

## Что нужно установить на ПК
1. Node.js 24 LTS: `winget install OpenJS.NodeJS.LTS`, затем pnpm: `npm install -g pnpm@10.34.6` (или `corepack enable` в окне администратора). Версия pnpm закреплена в `package.json` (`packageManager`).
2. Docker Desktop (или установленный PostgreSQL, или аккаунт Neon).
3. Git (уже есть).

## Рассмотрено и отклонено
- **SQLite:** проще, но на бесплатных хостингах диск временный, а Postgres ближе к реальному продукту и даёт полнотекстовый поиск и транзакции с блокировками.
- **Python (FastAPI) + React:** рабочий вариант, но типы между языками приходится генерировать из OpenAPI.
- **Next.js:** лишняя сложность для трёх человек в одном `app/`-каталоге, карта всё равно клиентская.
- **Java/Spring:** тяжелее и медленнее в доработке для хакатона; Java-шаблон в `.gitignore` и `CONTRIBUTING.md` остался от общего шаблона команды.
