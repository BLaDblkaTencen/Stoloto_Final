# Дизайн «Вместе»: мягкий необрутализм

Утверждённое направление визуала. Здесь живой макет главной и дизайн-токены, из которых собирается `shared/ui` (задача 3.3). Требования к экранам — в [DESIGN_BRIEF.md](../DESIGN_BRIEF.md), подписи статусов — в [DATA_MODEL.md](../DATA_MODEL.md).

## Файлы

| Файл | Что это |
| --- | --- |
| [home.html](home.html) | Макет главной: поиск, «Мои записи», фильтры по видам спорта, список и карта. Кликабельный |
| [tokens.css](tokens.css) | Все цвета, шрифты, радиусы, тени. Единственный источник, в коде значения не хардкодим |

**Как посмотреть:** открыть `docs/design/home.html` в браузере, сборка не нужна. Запасное состояние карты: дописать `?nomap` к адресу. Телефонный вид: DevTools → режим устройства, там появится переключатель «Список / Карта».

## Принципы стиля

- **Чёрная обводка 2px и жёсткая тень без размытия** (`--shadow-sm/md/lg`) у карточек, кнопок, полей, меток на карте. Это главный узнаваемый признак.
- **Пастельные заливки** только для смысла: вид спорта (палитра `--sport-*`) или статус (`--status-*`). Фон страницы голубой, карточки белые.
- **Заголовки** Comfortaa, **текст и интерфейс** Rubik. Любой текст ≥16px, основной 17px, кнопки и поля ≥48px.
- **Лёгкая «игривость»**: выбранный чип и стикеры «Мои записи» чуть повёрнуты (±1.5°). Карточки событий и формы не поворачиваем: их нужно читать.
- **Состояние не только цветом**: у бейджа всегда иконка и подпись. Режим «По заявке» на карте — метка с замком.
- Нажатие кнопки «вдавливает» её (сдвиг на тень), наведение — приподнимает.

## Подключение в приложении

Tailwind v4 уже настроен в [apps/web/src/index.css](../../apps/web/src/index.css): токены импортируются отсюда и пробрасываются в тему через `@theme inline reference`. Работают классы `bg-primary`, `text-ink`, `bg-status-success`, `rounded-lg`, `shadow-md`, `font-display`, `text-h2`; `text-sm` равен 16px, `text-xs` отключён. Новый токен из `tokens.css` добавляется туда же одной строкой.

`reference` обязателен: без него Tailwind выводит `--color-bg: var(--color-bg)`, то есть переменную, которая ссылается сама на себя и может перебить значение токена.

Шрифты Comfortaa и Rubik (лицензия OFL) подключены пакетами `@fontsource` в `apps/web/src/main.tsx`: они собираются вместе с приложением и не зависят от доступа к Google Fonts. Макет `home.html` по-прежнему берёт их из Google Fonts, для просмотра макета это не важно.

## Компоненты shared/ui

Готовые компоненты в [apps/web/src/shared/ui](../../apps/web/src/shared/ui), импорт одной строкой: `import { Button, StatusBadge } from '../../shared/ui'`. Все вживую — страница `/ui` в режиме разработки (`pnpm dev`), в сборку для экспертов она не попадает. Свои кнопки и бейджи на экранах не рисуем: так интерфейс остаётся единым.

| Компонент | Для чего |
| --- | --- |
| `Button`, `ButtonLink` | кнопки `primary` (записаться, найти), `dark` (подать заявку, создать), `secondary`, `danger`; `loading` на время запроса; размер `lg` |
| `StatusBadge` | статус записи, заявки организации или события: `<StatusBadge kind="registration" status="pending" />`, подпись и цвет из DATA_MODEL |
| `JoinModeBadge`, `Badge` | режим записи с дверью или замком; любой бейдж с иконкой (`8 из 16`, `Для новичков`) |
| `SportChip`, `Chip` | фильтр по виду спорта: цвет и иконка по `slug`, выбранный чип наклонён |
| `TextField`, `TextareaField`, `SelectField`, `RadioCards` | поля формы с подписью, подсказкой и ошибкой под полем (`error={fields.title}`) |
| `Alert` | сообщение над формой: ошибка запроса, предупреждение, успех |
| `Modal` | окно подтверждения с причиной: снять событие, отклонить заявку |
| `EmptyState`, `ErrorState`, `SkeletonList`, `Skeleton` | пусто, ошибка загрузки с кнопкой «Повторить», скелетоны вместо спиннеров |
| `Card`, `Avatar`, `Icon` | карточка (`tone` — цвет фона), аватар с инициалами, иконки из макета |
| `sportColor`, `sportIcon` | цвет и иконка вида спорта для своих элементов, например меток на карте. Свой вид спорта получает иконку по теме названия (`sportTheme` в `@sport/shared/sportThemes`: «Шашки» — фигура, «Верховая езда» — лошадь); тему не узнали — общая иконка `activity` |
| `eventPin`, `venuePin`, `pinIcon`, `venueTypeIcon` | метки карты для `L.divIcon` и иконки типов площадок (кафе — чашка, парк — дерево…) |
| `MapPopupCard`, `VenueCard`, `MapUnavailable` | попап события, карточка площадки с «С кем договориться» и кнопкой «Позвонить», «Карта недоступна» |

Окно, список и переключатели построены на системных элементах (`<dialog>`, `<select>`, radio): клавиатура, фокус и экранный диктор работают без отдельной библиотеки, поэтому shadcn/ui не понадобился.

## Карта (Leaflet)

Стиль карты уже собран в `shared/ui` ([map.ts](../../apps/web/src/shared/ui/map.ts), [map.css](../../apps/web/src/shared/ui/map.css), [MapParts.tsx](../../apps/web/src/shared/ui/MapParts.tsx)) и проверен в настоящем Leaflet 1.9: размеры меток, замок, попап 300px, кнопки масштаба 48px, атрибуция и текст не мельче 16px. Логику карты (данные, фильтры, выбор места) пишет участник 2.

```tsx
import L from 'leaflet';
import { MapContainer, Marker, Popup, TileLayer } from 'react-leaflet';
import { eventPin, JoinModeBadge, MapPopupCard, sportColor } from '../../shared/ui';

<MapContainer className="map-frame h-[780px]" center={[56.01, 92.853]} zoom={13}>
  <TileLayer url="https://tile.openstreetmap.org/{z}/{x}/{y}.png" attribution="© OpenStreetMap" />
  <Marker position={[e.lat, e.lng]} title={e.title} icon={L.divIcon(eventPin({ sportSlug: e.sport.slug, joinMode: e.joinMode, selected }))}>
    <Popup minWidth={300}>
      <MapPopupCard color={sportColor(e.sport.slug)} sport={e.sport.name} badge={<JoinModeBadge mode={e.joinMode} />} title={e.title} actions={…}>…</MapPopupCard>
    </Popup>
  </Marker>
</MapContainer>
```

- **Класс `map-frame` на контейнере обязателен:** без него остаются стили Leaflet по умолчанию (текст 12px, синие ссылки поверх наших кнопок).
- **`title` у маркера обязателен:** это подпись метки для экранного диктора, Leaflet делает метку доступной с клавиатуры.
- **Метки событий** (`eventPin`): 46px, выбранная 60px, цвет и иконка вида спорта, замок у «По заявке».
- **Метки площадок** (`venuePin`): иконка типа площадки; подходящие виду спорта — жёлтые 46px, остальные — приглушённые 36px.
- **Размер меток от масштаба карты** (`pinScale(zoom)`, параметр `scale`): до 13-го уровня — размеры выше, дальше каждый уровень приближения −10%, с 17-го — 0,6 (обычная метка 28px). Вблизи метки не закрывают соседние и точно стоят на месте; замок «По заявке» уменьшается не мельче 3/4.
- **Попап события:** карточка 300px с цветной шапкой (вид спорта и режим записи), датой, местом, уровнем, местами, организатором и двумя кнопками: «Подробнее» и «Записаться» / «Подать заявку».
- **Карточка площадки** (`VenueCard`, в попапе — `compact`): тип, адрес, часы, блок «С кем договориться» с кнопкой «Позвонить» (ссылка `tel:`); у открытых мест без контакта — «договариваться не нужно».
- **Список и карта на десктопе** стоят рядом: список высотой с карту (≈780px), прокрутка внутри. **На телефоне** переключатель «Список / Карта» над списком.
- **Запасное состояние** «Карта недоступна» обязательно: компонент `MapUnavailable`, в `home.html` — открыть с `?nomap`.
