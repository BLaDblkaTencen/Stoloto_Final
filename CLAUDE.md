# Правила работы (читать первым делом)

Проект: платформа совместных спортивных активностей (хакатон). Над ним параллельно работают 3 экземпляра Claude, каждый в своей ветке и своём git worktree. Контекст ТЗ: docs/TZ.md. Распределение: docs/OWNERSHIP.md. Киллер-фича: docs/KILLER_FEATURE.md.

## Правила параллельной работы
1. Работай ТОЛЬКО в своей зоне из docs/OWNERSHIP.md. Чужие файлы не правь — пиши в docs/REQUESTS.md (кому, что нужно).
2. Контракт первичен: форма API и модели данных — docs/api.md (REST-таблица; раздел WebSocket оставлен шаблоном и не нужен) и docs/DATA_MODEL.md. Меняешь контракт — отдельный маленький PR в main и сообщи команде, не молча.
3. Процесс команды — в CONTRIBUTING.md (он главнее). Коротко: в main напрямую не пушим, только PR (мёржит капитан); ветки feature/…, fix/…, chore/…; коммиты и PR на русском в повелительном наклонении; перед PR — git fetch && git rebase origin/main.
4. Не коммить секреты, БД-файлы, node_modules.
5. Бизнес-логика серверная: права и статусы проверяются на бэкенде, не только скрываются в UI.
6. Приоритет: сначала 6 базовых сценариев ТЗ, потом киллер-фича «Место встречи» (docs/KILLER_FEATURE.md), потом остальное. Карта не должна ломать основной сценарий: адрес всегда хранится текстом. Визуальные требования — docs/DESIGN_BRIEF.md.
7. UI: крупные шрифты (≥16px), высокий контраст, заметные статусы, mobile-first.
8. Язык интерфейса — русский.
9. Стек и правила БД — docs/STACK.md. Всё программное обеспечение и сервисы только бесплатные. Схема БД — по модулям в apps/api/src/db/schema, без файлов миграций в прототипе (db:push + db:seed).
10. Авторизация настоящая (email + пароль, Argon2id, сессия в HttpOnly-cookie), демо-аккаунты сохраняются кнопками на экране входа. Пароли не хранить и не логировать в открытом виде; роль admin регистрацией получить нельзя; права всегда по роли из сессии на сервере.
