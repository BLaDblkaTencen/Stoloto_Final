# Как мы работаем

Команда: капитан (ревью и мёрж) и два разработчика. Каждый берёт свою задачу и ведёт её в отдельной ветке.

## Один раз перед началом

1. Склонировать репо и открыть папку в VS Code.
2. Поставить расширения, которые предложит VS Code (список в `.vscode/extensions.json`).
3. Ничего не настраивать под себя в форматировании: стиль задают `.editorconfig`, `.prettierrc.json` и `.vscode/settings.json`, форматирование срабатывает при сохранении.

## Цикл работы над задачей

```bash
# 1. Взять свежий main
git switch main
git pull

# 2. Создать ветку под задачу
git switch -c feature/lobby-page

# 3. Работать и коммитить небольшими шагами
git add .
git commit -m "Добавить страницу лобби"

# 4. Подтянуть изменения коллег (делать хотя бы раз в пару часов)
git fetch
git rebase origin/main

# 5. Отправить ветку и открыть PR в main
git push -u origin feature/lobby-page
gh pr create --fill
```

После мёржа ветку удаляем и начинаем следующую задачу с шага 1.

## Правила

- **В `main` напрямую не пушим.** Только через PR, мёржит капитан.
- **Названия веток:** `feature/...` — новая функциональность, `fix/...` — исправление, `chore/...` — настройка и инфраструктура.
- **Коммиты и PR пишем на русском**, в повелительном наклонении: «Добавить чат в лобби», «Исправить отключение игрока».
- **PR маленькие.** Лучше три PR по часу работы, чем один на полдня: их быстрее проверить и меньше конфликтов.
- **Делим задачи по модулям**, чтобы двое не правили одни и те же файлы одновременно. Если пересечение неизбежно — договориться в чате, кто первый.
- **Контракт между фронтом и бэком** (REST-эндпоинты и сообщения WebSocket для мультиплеера) описываем в `docs/api.md` до того, как начинаем писать код. Так фронт и бэк можно делать параллельно.
- **Секреты не коммитим.** Локальные настройки — в `.env` (он в `.gitignore`), пример с пустыми значениями — в `.env.example`.

## Если случился конфликт при rebase

1. VS Code подсветит конфликтующие файлы во вкладке Source Control.
2. Для каждого файла выбрать нужный вариант (Accept Current / Incoming / Both), сохранить.
3. `git add <файл>` и `git rebase --continue`.
4. Отправить ветку: `git push --force-with-lease`. Только в свою ветку, никогда в `main`.
